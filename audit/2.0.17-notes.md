## 一、截图与录屏图标

实际安装包新增三套 PNG 图标，每套有 60、120、180 像素三种密度：

- **截图**：蓝色渐变，白色取景框与相机符号。
- **录屏**：红色渐变，白色录制圆环与圆点。
- **应用选择器**：紫色渐变，白色应用网格／更多应用符号。

截图／录屏继续使用原 AppCell 和圆盘应用图标组件：不改变其尺寸、承载底板、间距、槽位和形状参数；图块内容使用全彩、AlwaysOriginal 的实际位图，不是系统未安装应用的白色占位图。

### 白图标兼容性修正

2.0.16 的 UIImage 私有图标接口签名检查只接受 `q/Q`（64 位整数）的 format 参数；遇到 `i/I`（int）会跳过自定义图标钩子。这是源码中可确认的兼容漏洞，但尚未从用户设备日志证明它是白图标的唯一原因。

2.0.17 为两种位宽分别提供匹配的原函数适配器，对两个精确动作 ID 返回图标，其他应用的请求参数和原结果继续透传。资源路径从实际加载 dylib 的位置解析，保留 RootHide 前缀，不硬编码分析机目录。资源缺失时仍保留彩色矢量兜底。

安装后请重新载入桌面，让原进程内的 ReflectManager／SwiftUI 图标缓存重新建立；不要仅覆盖文件后继续观察旧进程缓存。

## 二、圆盘中心应用选择器

### 操作

1. 展开 Stheno 圆盘。
2. 点击中心的紫色网格图标。
3. 在简洁面板中直接浏览，或输入名称／应用标识搜索。
4. 点击目标应用，通过原生浮窗启动路径打开。
5. 点击关闭或面板外空白区域可取消。

**当前产品假设：选择器用于临时打开未加入圆盘的应用，不自动把它添加到圆盘。**本轮已在执行前说明这一默认行为。原系统／用户应用列表中的开关仍负责持久加入或移出圆盘。

面板只显示原生目录中的真实应用，减去当前已加入圆盘的应用，合并重复标识，并排除截图／录屏这类虚拟系统动作。选择时再次检查成员关系，避免列表打开后应用状态变化仍误提交。

### 外观与布局

- 圆角、磨砂背景面板，顶部显示图标、标题、关闭按钮与搜索框。
- 应用列表使用普通应用图标和名称，没有增加复杂的分类或多层菜单。
- 键盘出现时使用实际可用空间调整高度；空间较小时改用紧凑标题布局，不通过虚构最小高度覆盖键盘。
- 兼容减少动态效果设置。
- 只在打开面板时创建临时的可输入窗口，关闭后释放，并恢复之前合适的 key window；中心图标本身附着原 Stheno 宿主窗口。

### 中心位置和原圆盘逻辑

中心入口不是插进 App 数组的第 N 个项目，也不参与圆环角度计算。原同心环数量、App 顺序、半径、圆盘／半圆／直角／任意模式都不改。

它从原生 RingEnv getter 读取 offset、scale、radius、iconWidth，使用原圆心 `P + offset`，不将 offset 再乘 scale。位置从固定屏幕坐标转换到真实宿主窗口。按钮直径以中心空白为上限，不挤开普通图标；当内圈空白小到不足以容纳可用入口时隐藏，而不是偷偷放大半径或覆盖应用。

编辑、快速设置、相关设置页、圆盘折叠状态下隐藏／禁用中心入口。其覆盖层在按钮之外返回 nil，不拦截其他圆盘或屏幕操作。

### 动画

- 中心图标具有按下反馈，并随圆盘位置、缩放和透明度变化。
- 展开使用有原生参数依据的弹簧插值，折叠使用 0.15 秒退场节奏；透明度从同一插值 scale 推导。
- 选择面板有弹簧出现、淡出／缩小退出动画。
- 目标 App 的启动复用原 selected-launch SwiftUI `withAnimation` 闭包，不以普通 UIApplication 全屏启动替代。

需要准确限定：中心 UIKit 控件不是原 SwiftUI RingView 渲染子树的一部分。根据原状态和参数跟随的动画是有依据的近似，尚未真机证明逐帧完全同步。横屏坐标／触摸表现亦需设备验收。

## 三、保留截图／录屏行为

- 录屏图标为静态功能图标，本版不宣称动态红环状态。
- 截图／录屏前显式隐藏新增中心入口和选择面板，再继续既有收起圆盘及延时执行流程。
- 动画中的面板可被截图前或后台事件立即关闭；关闭完成只回调一次，不重复提交应用启动。

## 四、原生桥接与所有权

新增 `ChooserNative.S` 只封装已经核对的原 getter、目录快照和启动函数，保留 x20/x21/LR 与 PAC 约定。

目录复制使用 GlobalEnv 的 user/system 原 Array<App>，在主线程将 name/id String 复制为 Foundation 值；当前圆盘选择来自 DeviceEnv 已保存的 manager 集合。所有 +1 原生数组与模型引用在读取后释放，不解析激活值，也不重写 `Apps`。

临时启动桥：NSString → 原 Swift String bridge → 原 ReflectManager builder → 原 selected-launch 动画闭包 → 既有浮窗 admission。原生 builder 消费输入 String 的所有权，调用方不重复释放 String words；模型在动画提交后释放调用方引用。

原来的 SystemActionNative、SystemActionDispatch、系统列表插入、两个动作 ID、保存恢复判断以及 SystemCapture 后端等九个文件，都与已交付 2.0.16 的仓库 blob 一致。

## 六、验证边界与安装后检查

**本版未在真机安装或运行。**设计预览是示意图，不是新版本实机截图。不能将编译成功、像素验证或模拟接口测试当作实际触摸／显示／动画已确认。

安装并注销后，建议依次检查：

1. 系统选择列表及圆盘中截图／录屏是否显示蓝色和红色图块。
2. 新紫色中心入口是否位于实际圆心，移动／缩放／旋转时是否跟随且不挡住其他应用。
3. 打开面板后，已加入圆盘的 App 是否确实被排除；搜索、取消及键盘收起是否正常。
4. 点未加入的 App 是否以浮窗打开，关闭后是否没有自动加入圆盘。
5. 面板出现／退出与 App 浮窗原生动画是否自然；横竖屏都需确认。
6. 已工作的截图／录屏仍能触发，且不会包含新增入口的退场残影。

本版不调整先前定档的键盘与通知声音问题，也未更改继承安装脚本可能覆盖偏好的旧风险。
