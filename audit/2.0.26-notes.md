## 一、浮窗键盘打开时自动放大、关闭时恢复

旧候选由窗口拖动 setup 登记，但浮窗内容触摸通常直接穿透给被托管应用，不经过该 setup。因此真实编辑不必然产生键盘放大的候选；仅调整等待时间或被动命中判断不能补全这条路径。

本版改为应用内真实编辑开始及键盘交付阶段发布输入焦点，经版本化、带时间戳的 Darwin notify 状态交给 SpringBoard，再匹配非最小化的原生浮窗模型。普通点击/拖动不再直接证明文本输入归属；焦点与键盘 frame 先后到达均有协调路径。

保留原有放大几何、原生动画入口、原尺寸快照恢复与最小化清理；选择面板使用键盘时暂停应用浮窗几何路径，避免面板搜索错误放大旧浮窗。全局停用条件仍受检查。

## 二、中心选择面板的键盘输入

不再把圆盘渲染窗口的 key 状态和 UITextField 的 first responder 状态，直接当成 SpringBoard 已授予实际键盘输入。

本版使用原生 `SBFWindow` 派生输入窗口，在本次面板会话内申请 `SBWorkspaceKeyboardFocusController` 的窗口焦点断言，运行时核验相关接口。一个 UIKit 控制器和真实 UITextField 管理挂载、可见、key 与关闭生命周期，移除计时轮询和第二个 SwiftUI 焦点所有者。关闭开始即停止新焦点请求、结束编辑并释放断言；保留中文输入法 marked text 保护。

面板不再继承圆盘渲染窗口的层级。该实现已编译，但私有接口可用性、键盘实际呈现/叠层及按键触摸仍需目标设备验收，静态头文件和主机测试不能证明这些行为。

## 三、实际写入原主二进制的桥接

- 将 `native.S` 的 **23 个原生入口、1,504 B** 迁入主核既有可执行空区 `0xda600..0xdabe0`。
- 同核调用改为直接目标；辅助库保留 ABI 转发入口。
- 不移动原函数、原 VM 布局或原动画目标；保留 PAC、Swift 上下文和 Published setter 所有权规则。
- 手势与系统动作两个 SpringBoard 辅助库合并为一个 image；应用侧 `SthenoKeyboardInset` 仍独立。
- 这是二进制定点迁移加独立源码辅助库，不是恢复原作者完整工程，也没有把全部 Swift/ObjC 功能塞入主核空区。

## 六、真机待验收

本版尚无目标设备安装反馈。不能将 CI 通过表述为面板键盘和浮窗自动放大已在真机修好。

建议先验证：
1. 在桌面及前台应用上呼出中心面板，自动弹键盘，点击搜索框可输入中文、英文和应用 ID；关闭后键盘正常退出，快速重开可再次输入。
2. 不先拖动浮窗，直接点输入框：打开键盘自动放大，收起后恢复原尺寸/位置；连续重复并切换两款应用。
3. 开键盘后停靠，缩略图可单次点击还原；迟到的键盘 frame 不再次放大最小化窗口。
4. 检查中心位置/划入悬停、普通应用松手启动、原圆盘退场，以及控制中心/通知中心/锁屏后的恢复。

通知提示音问题本版没有新的真机证据，不宣称已解决。
