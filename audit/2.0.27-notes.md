## 1. 浮窗放大滞后：修同步，不调等待时间

2.0.26 的输入总线只发布归属声明，不带同一次通知的物理键盘帧。SpringBoard 的补偿仅在本进程已有不足一秒的缓存帧时执行；claim 先到时仍会等待另一条原生回调。该缓存也没有绑定 bundle/session。源码中的一秒是旧缓存的准入上限，不是已找到的固定一秒定时器；尚未对真机延迟作分段测量。

本版：

- 在应用侧真实 `WillShow` / `WillChangeFrame` 投递入口取得未做 scene 归一化的物理键盘帧，与已确认的输入归属组成完整快照。
- 使用 v2 双缓冲快照：先写非活动槽，再翻转包含 active/frame/序列/时间戳的提交字，最后宣布 owner、确认提交并发通知。读取前后验证 owner 与提交字，允许通知合并，不按回调次数推导状态。
- SpringBoard 收到有效快照即在当前主线程原生动画事务内协调几何，不再以另一条本地缓存帧为必要条件。
- IPC 唤醒只执行几何/布局协调，不重放原生 `keyboard-show`；真实原生通知仍调用原逻辑一次。重复输入声明不会重存放大后的尺寸作为还原快照。
- 真实编辑事件直接缓存弱引用响应者；缓存仍有效时不再反复遍历整棵视图树。特殊输入控件仍保留受限遍历回退。
- 晚到的 A hide 只结束 A 自己的状态，不再对共享 owner 做 read-then-clear，从而避免抹掉新 owner B。
- 最小化、横竖方向、物理帧合法性、全局开关及面板本地输入隔离继续生效。面板接管/退出更新读取时间边界，旧快照不得恢复应用几何。

没有改动现有 650 ms preview 失效、布局稳定采样参数或原版弹簧参数。快照时效检查是拒绝旧事件的条件，不是定时等待。

## 2. 面板仍无键盘：补齐场景路由与真实失败检查

2.0.26 即使使用 SBFWindow，输入 scene 仍来自圆盘渲染宿主；只请求了窗口 stealing，未持有 SpringBoard scene focus lock。返回 nil 仍允许编辑，并消耗唯一的自动聚焦机会。

本版：

- 通过 SpringBoard 的活动显示窗口场景选择同屏输入 scene，不再直接把圆盘渲染 scene 当作输入宿主。
- 每次面板会话成对持有 scene focus lock 与窗口 focus-stealing assertion；方法的返回值和参数 ABI 均检查。第二步失败立即释放第一步，关闭按窗口→场景顺序幂等撤销。
- 先建立路由，再请求 key；实际 field 聚焦仍要求 appeared、presented、attached、key、active、未被系统界面遮挡。
- nil 路由不消耗自动聚焦机会，也不再被当作成功；真正失败时面板显示简短输入焦点提示。
- 检查 `becomeFirstResponder` 的返回值，保持真实 UITextField 与中文 marked text 保护；不添加定时轮询、重复 reloadInputViews 或全局键盘策略 hook。
- 主动关闭先标记 closing；释放断言触发的失焦通知不打断原 150 ms 退场/提交顺序。申请过程中已经关闭的会话会立即释放迟到令牌。

以上是补全代码中可确认缺口的候选修复。相邻 iOS 17 runtime headers 的接口存在性、token 非空、key 或 first responder 成功，都不能单独证明 iOS 17.3.1 软件键盘已呈现或按键已送达。

## 5. 安装与真机验收

安装后注销/重启 SpringBoard，并结束后重新打开用于测试的应用，避免原进程仍加载 2.0.26 的 v1 输入协议。

优先只验证：
1. 不先拖动浮窗，直接点输入框：放大是否与键盘一起开始，而非键盘出现后再等约一秒；收起键盘后尺寸和位置是否正确还原。
2. 桌面及前台应用上打开中心面板：是否出现软件键盘，中文/英文实际按键是否能输入；关闭、快速重开均需检查。
3. 若面板仍无键盘，记录是否出现“搜索键盘未取得系统输入焦点”或“搜索输入框尚未取得响应焦点”提示；这能区分路由申请失败和后续呈现问题。不要只凭光标显示推断键盘正常。
4. 开键盘后停靠、单击还原，并检查原圆盘位置/悬停/退场未退化。

尚无本版真机结果。若完整路由/key/响应者均成立但系统键盘仍不呈现，仍需设备上的输入仲裁/宿主/叠层证据，不继续用延时重试代替定位。通知提示音不在本版已确认修复范围。
