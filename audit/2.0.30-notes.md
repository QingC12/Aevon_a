# 2.0.30 相邻版本键盘与过渡比较

## 用户真机反馈是本轮验收基准

- 2.0.28：用户确认浮窗打开键盘、输入框/工具栏表现很好，似乎所有应用均正常，但放大时有一下抖动。
- 2.0.29：用户确认输入框又被键盘略遮挡；放大动画不流畅且仍抖动，要求接入原版过渡。
- 不能因键盘动态库字节未变，就将宿主浮窗动画对输入可见区域/运动时序的影响排除。29 的独立放大弹簧是本轮需要撤销的已知行为差异；没有设备逐帧采样，不把它描述为已确证的唯一遮挡根因。

## 28 → 29 的实际差异

上轮独立验包已确认：34 个普通安装文件只改 SpringBoard 的 SthenoSystemActions.dylib，315760 → 315904 B；原主核、SthenoKeyboard.dylib、SthenoKeyboardInset.dylib、Orion 及其余 33 个文件逐字节相同。

Keyboard.m 的完整差异只有：
1. 真实输入归属变化时调用 STHGestureInputFocusChanged，退役该模型旧手势；
2. 浮窗目标 scale/offset 写入从原调用事务，改为额外包入 STHCardRunExpansion；response 为 .25/nativeSpeed，但阻尼下限被设为 1。

第 2 项把浮窗和原键盘避让的过渡拆开；它不是“没有动键盘效果”的充分条件。29 中两套 spring 的调用边界可由精确旧源码回放证明，视觉影响与持续遮挡的具体关系仍需真机验证。

## 30 的最小修复

- 删除 CardExpansion.S、对应编译对象及导出，并移除该功能的旧发行闸门。
- 还原 28 的直接 STHNativeSetKeyboardGeometry 写入；原生 Will 回调内仍沿用原调用者的 spring，不再嵌套独立弹簧。
- 晚到的跨进程 owner 确认沿用 28 既有的原参数 withAnimation fallback。不新增曲线、速度、阻尼、键盘高度、偏移补偿或固定等待。
- 29 的 Gesture.m 输入接管/迟到手势清理完整保留，SHA-256 与已发布 29 一致。没有为恢复动画退回先前的触摸缺口。
- 80 个其它生产源码/脚本/资源继续锁定为 28；编译脚本只允许版本变化，原核 ABI 桥及原圆盘完全不改。

## 抖动的一个可复现状态缺口

原 inputOwnerChanged 只要得到 nil 就立即停止布局、还原浮窗、清空 owner/candidate；而原 snapshot API 对真正失焦、暂时读取失败、部分提交、过期等均可返回 false。若下一次读回同一 model，则又保存快照并重新放大。这个还原 → 再放大可以由生产代码构造，不需要改变键盘几何。

30 只在已有 owner/candidate 且本次无匹配时，将同一原 API 的复核投递到下一次 main queue；首次空读不改浮窗、不停布局、不清状态。只复核一次：
- 同一 owner 恢复：保留当前目标与初始 saved 快照，零几何写入；
- 仍空：沿原过渡还原一次，不递归重试；
- 新的有效 owner/native delivery、真实 hide、本地输入切换、相关模型最小化：代数作废旧复核，避免迟到回调改变新状态。

没有定时器、轮询、延长输入租约或改变 750ms/3s 阈值；不重放原生 show/hide，也不等待 DidShow。实际键盘 hide 仍立即走原还原路径。真正失焦最多增加一轮主队列确认，晚于该轮才恢复的快照仍可能触发还原；这不是无限宽限，也不声称穷尽所有抖动成因。

## 新回归避免旧测试盲点

旧测试的 card 矩形为固定值，几何 setter 改 scale/offset 后，后续矩形读取并不反映变化。新增 test_native_card_transition.m 根据当前 scale/offset 推导 card，截获被测代码真实投递的 main queue 闭包，用可控队列逐轮执行。

精确 SHA 锁定的 29 Keyboard.m 负例分别检查：
1. 首次几何写入不应进入 card-only 嵌套事务，旧版断言失败；
2. 短暂空快照不应立即还原已有浮窗，旧版断言失败。

新实现需覆盖 200 轮动态卡片：原生事务、frame-first/claim-first、短暂空读恢复、持续失焦单次还原、同 owner 不重开动画、有效 native 事件/hide/local-input/dock 取消旧闭包、原始 snapshot 不被覆盖及原生 show 单次交付。既有 29 全屏键盘转浮窗/双浮窗/停靠/迟到回调回归仍执行。
