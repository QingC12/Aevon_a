# Stheno arm64e portrait gestures (binary-derived test build)

This private project reconstructs the requested portrait-gesture dispatch from the supplied Stheno binary. It is a replacement gesture module with ABI bridges, **not a recovery of the original full Swift source tree**.

## 2.0.16 native system-action slots

Adds **截图 / 录屏** at the top of the existing System app picker, in that order. The original AppCell Toggle, saved `Apps` list, ReflectManager icon cache and ring layout are reused. These are opt-in action identifiers, not installed app bundles. Both icons are full-color 60pt application tiles; the existing row/ring supplies the exact same frame, circular carrier, hit target, radius and geometry as ordinary applications. All four existing carrier shapes remain native.

`SthenoSystemActions.dylib` is a separate helper. A narrowly verified System-array publication patch at `0xfe30` prepends genuine `Stheno.App(name,id)` values using the ORIGINAL specialized COW allocator (`0x47710`) and String bridges; it does not create fake Swift metadata, globally modify LaunchServices, or reorder the ring. A guarded early admission patch (`0x47e8`) consumes the exact action IDs before `_floatings` insertion or scene creation; normal models replay the native PAC prologue. Presentation at `0x41a9c` has a second guard then passes through unchanged `0xd9440` to the accepted first-presentation logic. Two exact saved-app validation branch guards (`0x81968`, `0x81c78`) preserve these virtual IDs during native `Apps` cleanup/restoration; all real installed-App validity results and unrelated IDs retain the original branches. They do not claim an installed SBApplication or launch a dummy app.

Actions execute only after an explicit icon selection. The original ring-collapse animation and transient quick-setting hide run first; capture is deferred 0.35 seconds. Screenshot uses SpringBoard's native screenshot entry. Recording toggles native SYSTEM recording, microphone disabled; no in-app ReplayKit fallback or consent-flag edits. Missing/incompatible APIs and unconfirmed recording state report an error, rather than pretending an app was launched or a movie saved. Saving, native status presentation, OS restrictions and app content protection remain system-managed and need device acceptance.

All 38 frozen keyboard/gesture runtime inputs, existing helper compiler commands, setting defaults/resources and installer scripts remain unchanged. New host tests cover catalog IDs, stable ordering, native-array ownership-copy seams, duplicate taps, typed capture APIs, and original-path isolation. **No device installation/execution is claimed; consult final release notes for completed CI and artifact checks.**

## 2.0.15 whole-plugin audit and safe cleanup

This maintenance release removes confirmed dead source: comment-only `GestureRules.h`/test placeholders, an unused old keyboard-inset math header/test, the superseded uncompiled `EditorVisibility.m`, the unreferenced `_STHNativeAnimatePhysicalKeyboard` bridge and a test-only geometry helper. Active settings, gesture decisions, keyboard geometry and native animation entry points remain unchanged. Tuple-scale wrappers were already absent. `LayoutProbe` and `NotificationPolicy` remain live: the former reports bounded class/rect/flags for the unresolved Douyin row, the latter only reads/logs one preference bit for the sound investigation. Python caches/generated build products are ignored and excluded from the DEB.

The `data.tar.xz` compressor now uses a deterministic LZMA2 parameter set, checks that decompression is byte-identical before packaging, and records before/after archive sizes in the manifest. On the prior2.0.14 payload this reduced the data archive from465,936 to460,508 bytes (5,428 bytes) with every decompressed path, file byte and mode unchanged. This is an archive-only reduction; it does not strip original code or remove toggles.

`audit/plugin-audit-2.0.15.md` records the read-only toggle/source audit, installer finding and unresolved mappings; `audit/maintenance-2.0.15.md` records exact cleanup and package-safety checks. These reports remain in source control for traceability but the build uses an explicit allow-list and does not ship audit documents. No setting menu, setting bit/default, hook feature, installer script or original package component was changed. The main global audit finding is inherited `postinst`: under its fallback/template-copy conditions it can replace the complete saved preference plist, potentially resetting user bits/app lists. This release leaves that installation behavior untouched.

## Behavior

- Existing hit-region geometry and width calculations remain in the original image.
- Red sides: one tap invokes native dock/minimize; .25s stationary hold arms native window movement.
- Green bottom corners: reuse native corner scaling.
- Blue bottom-left: hold for .25s to switch from portrait to landscape. In landscape, hold the middle of either original side edge or the lower-left blue segment for .25s to return to portrait.
- Blue bottom-right: hold for .25s to restore the model initializer's four scale values (.8,1,1,.8) and clear native aspect trim.
- Yellow bottom-center: touch and drag immediately to move; release is passed once to the original Stheno edge-middle drag-end routine with hit class 4 and its long-press latch cleared. Native flick threshold, cleanup and animation decide closing. There is no .25s hold requirement, 24pt threshold or custom close action.
- Yellow continuous movement never changes its saved edge-middle hit class. The native close recognition code is byte-for-byte preserved, and build.py asserts this before signing.
- Movement and corner scaling use original Stheno update paths. Docking uses the original SwiftUI spring transaction; closing uses the original native release path. Restoring a docked window and switching orientations retain their original callbacks.
- Sileo lists `stheno` at `2.0.16`. The Debian control file retains `stheno` as its short description.
- Keyboard: the touched portrait floating card is sized to the full screen width and horizontally centered, without the old 12pt margin or 35% cap. Hide restores the snapshot, unless the user changed it while typing. Hardware/floating keyboards and landscape retain native behavior.
- Keyboard coordinates now prefer a fresh, per-bundle snapshot published by SpringBoard: the native final card rectangle (which already includes final scale) and docked physical keyboard rectangle. Application notifications and UIKit insets map the keyboard using BOTH the card origin and its screen-to-app scale. Top-positioned cards can have zero obstruction; lower cards get the correct larger local obstruction. Native InputSetHost/physical-screen conversion remains a fallback if the host snapshot is absent. The native card's `finalFrame` is already computed as base frame times final scale at `0x9c73c–0x9c758`; it is not multiplied by scale a second time.
- In2.0.10 the FIRST keyboard target is synchronous: focus pre-announces the predicted full-width card, a validated physical WillShow frame maps immediately, and the actual target is committed after Keyboard.m sets native geometry. No keyboard notices are queued or replayed. Pending UIKit queries retain native values instead of forcing zero. Later corrections retain the pairwise stability filter and double-buffer transport; sustained changes remain possible. Original first show/hide and floating-window springs are retained. Settled scene-only corrections use zero additional duration rather than restarting an expired keyboard animation.
- Cross-process layout retains the v4 double-buffer protocol, silent heartbeat and per-bundle freshness. A separate predicted-card slot enables same-call-stack initial conversion; first physical target is validated. If no trustworthy initial mapping exists, native data passes through without an artificial wait.
- In2.0.11, composer protection has its own lifecycle, independent of whether the keyboard rectangle changed. Every WillShow/DidShow, valid host activation and focus change starts/renews measurement. It keeps bounded10Hz checks while the scoped keyboard is active (30Hz for1.2s after events), not only one1.2s scan after a geometry correction. All app windows are searched for an editable first responder; noneditable responders no longer abort the entire search. Responder-chain capture supplements standard text-view discovery without reading input text.
- App-owned toolbars can be nested in nearby ancestor branches and use arbitrary private class names. A bounded control-evidence and geometric-contiguity scan collects nearby rows under a small editor container. No whole comment page/window is moved. Only positive obstruction is corrected, and each own transform is restored on hide/focus change/removal unless the app independently changed it. Class/row detection remains heuristic and is not yet verified on the user's app versions.

Lifecycle updates are synchronous on main; there is no unversioned async hide block. Each publisher session clears its native candidate/source/timestamp and validates both card and keyboard before an initial commit.
- If a validated physical keyboard assembly is visible in the APP process, its repeated current samples are mapped through the same hosted-card geometry to check the composer. Fullscreen or virtual scene-sized keyboard containers that do not fit the physical screen are rejected. No forced27pt correction or cold-launch rectangle reuse is applied.
- Measured editor stages and failure reasons are now sent over the layout channel to the SpringBoard log (`editor-report`), since the supplied log had no QQ/Minis editor measurement lines. No popup-window height/origin enters the hosted scene path. Refresh commits canonical state before sending Will/DidChangeFrame, does not require an observer to read userInfo, reuses real keyboard animation metadata, and invalidates on hide/host expiry.
- The app adapter is explicitly excluded from SpringBoard, Spotlight and the keyboard process, preserving the publisher's physical notifications. Current visible input-set containers plus visible adjacent keyboard accessory/candidate/toolbar views form the live physical keyboard region. Old notification rectangles are no longer unioned into it; current native physical notification is only a fallback. Debug output identifies source, native rectangle and age. The log's27pt source changes alone do not prove which top is physically visible; device verification remains necessary.
- The new app coordinate correction requires a fresh, per-bundle active host snapshot. It does not stay enabled after keyboard hide/fullscreen return merely because a cached legacy frontmost value says so.
- First presentation of each manager uses the same default tuple and aspect-clear body as bottom-right reset, followed by native geometry refresh. ## Build

`python3 build.py` on macOS with Xcode's iPhoneOS SDK. The workflow is `.github/workflows/build.yml`.

The script verifies the input DEB and exact arm64e main-image SHA-256, assembles PAC-preserving entry stubs and original-entry trampolines, compiles the explicitly enumerated main/helper sources, signs each changed Mach-O file, verifies signatures, packs a Debian archive, and reads every archive member back. It recompresses only the data TAR and asserts decompression is byte-identical before packaging. The resulting file count is recorded in `build-manifest.json`. Eight original components and the gesture helper remain arm64e-only; the bundled Orion runtime is arm64e-only as well.

Only gesture entry code, the private Orion load path, and an added app-side keyboard-inset helper load command are patched. Media and package-maintenance logic are retained. The original app-side keyboard code is preserved; the helper wraps its result after the original hooks initialize. Source model offsets are specific to the supplied sample, so the script rejects other binaries.

## Orion is bundled privately

The main image imports 79 symbols from Orion. This build does not delete that code or fake its symbols: it includes the official Theos Orion 1.0.2 arm64e runtime at `Library/MobileSubstrate/DynamicLibraries/.stheno/Orion` and links to it through `@loader_path/.stheno/Orion`. The private runtime has a distinct install name `@rpath/SthenoOrion`, preventing it from occupying the usual global Orion framework path. Its Substrate dependency uses RootHide's `.jbroot` path from the parent directory.

`Depends` no longer contains `dev.theos.orion`; only the existing MobileSubstrate and firmware dependencies remain. No other app or tweak is told that a global Orion package is installed. Do not remove an Orion package that other installed tweaks need.

Official source/release: https://github.com/theos/orion/releases/tag/1.0.2

Release archive SHA-256: `67ea96da8983a792bc9e5549472c2e597b84024c66bce888ce19e7940e413e55`

Input arm64e runtime SHA-256: `e7cbd6e055d9ec30c750741c9a2831d73c5ce7efaf812053e7b279a4e92dbe85`

The MIT license is preserved as `.stheno/Orion-LICENSE.txt` in the DEB. `test_embed_orion.py` verifies all imports, private resolution, unchanged load-command ordinals and code/fixup bytes, rejects a modified runtime, and checks the license. CI signs and verifies the private runtime along with the patched core and gesture helper.

## Validation

Build, archive and code-signature checks do not verify behavior in SpringBoard. This package is a **device-untested test build**. Confirm hit regions, side tap/hold competition, scaling, landscape rotation, default-size restoration, multiple floating windows, and docking/un-docking on the actual RootHide device. Prior arm64e repack was reported by the user to load successfully; that report does not establish this patch's runtime behavior.

The original install/uninstall scripts are retained. Installation may reset preferences and restart cfprefsd. Keep the previously working DEB available for rollback. No GitHub token is stored in this repository.
