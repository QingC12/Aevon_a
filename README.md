# Stheno arm64e portrait gestures (binary-derived test build)

This private project reconstructs the requested portrait-gesture dispatch from the supplied Stheno binary. It is a replacement gesture module with ABI bridges, **not a recovery of the original full Swift source tree**.

# Stheno 2.0.22 center visibility recovery and reliable search input

The ring-follow overlay is now treated as a permanent transparent carrier. Its registered parent is no longer hidden by the center chooser for ring collapse, small center holes, capture suppression, or system gating; only the private glyph hosting view and its interaction state are toggled. When system visibility unblocks, the tick path repairs a stale hidden carrier. Window/scene lifecycle notifications trigger host rescans, and a short bounded host check rebinds when SpringBoard replaces the Stheno Container view. Rebinding resets placement and state before the live native ring snapshot is applied. Release admission and original ring collapse are unchanged.

The search control is now a UIKit `UITextField` hosted through `UIViewRepresentable`, still bound to the same query and compact SwiftUI card. It requests `becomeFirstResponder()` only when attached to the actual panel UIWindow and that window owns key status. A bounded retry handles either attachment or key acquisition arriving first; a key-window notification restarts the request after a handoff. Closing cancels focus and ends editing before detach. Previous-key restoration is restricted to the same visible, foreground-active scene and only when the chooser owned key at teardown.

CI contracts now cover the carrier hide regression, host replacement rebinding, key-gated responder, and bounded focus lifecycle. These are host/source checks; intermittent SpringBoard visibility and keyboard presentation still need device verification.

# Stheno 2.0.21 center hover and search keyboard

Center selection now follows the normal App hover response while preserving the existing pan-follow center position: white backing brightness, whole-tile 1.45× scale, and a 2.3× native icon-width screen-up hop scaled with the ring's current presentation scale. The hop is only visual; the center origin and native hole hit geometry remain fixed. It begins only after the gesture enters the center following an outside sample, matching the actual swipe-to-center interaction, and returns to rest when the pointer leaves or the gesture ends. The selected App/release path and original ring auto-collapse remain untouched.

The chooser search field is now explicitly bound to SwiftUI `@FocusState`. Its separate panel UIWindow is a key-window-capable subclass, is created only in the foreground-active ring scene, and reacquires key status before the panel enters its visible state. Showing the panel requests search focus so the software keyboard appears; hiding or closing it resigns editing and restores the previous key window only when the panel owned key status.

The compact 360pt panel, short-list content sizing, long-list scrolling, and original ring-follow coordinate conversion are retained. Host contracts cover the native-lift constants, focus wiring, foreground scene, and key-window handoff. This change is not yet device-verified.

## 2.0.20 center admission, compact chooser and audit fixes

The center tile now uses the same host-local coordinate basis as the native recognizer when available, instead of applying an unverified second fixed-screen conversion. Its independent large upward lift is removed, so it remains centered with the ring rather than appearing as a detached extra item. The original ring's carrier geometry and release/collapse routines remain unchanged; the helper still does not add a ring slot. Exact insertion into the proprietary RingView render subtree was not available from the recovered sources, so the helper uses the original native animation entry and the verified host coordinate conversion without rewriting the original SwiftUI renderer.

Center admission now requires an actual outside-to-center crossing during the current gesture, movement, and a non-cancelled release. Opening the ring, releasing at the edge, a cancelled recognizer, or an already-centered initial touch cannot submit the chooser. The native end path still runs first and the decision is consumed once afterward.

The chooser panel is content-sized for empty, short and filtered lists, caps long results to a compact scrolling region, and reduces the width cap to 360 points. Scrim, keyboard window, hit targets, search, key-window restoration and panel transition behavior remain unchanged.

The audit also fixes several independent state bugs: an existing Stheno preference file is never replaced during installation or upgrade; keyboard focus ownership is captured at a real content gesture setup rather than passive scene hit-testing, and a new candidate cannot steal an active floating card's keyboard geometry; preview rectangles carry a session token and cannot leak into a later keyboard session; the native keyboard exclusion hit code is preserved; and landscape dock reflow leaves native orientation-dependent offsets untouched until an exact mapping is available. These changes are host-tested and still require device acceptance.

The notification-sound audit found no direct global mute or audio playback path in Stheno. The inherited `isApplicationForeground:` hook changes foreground classification only when the plugin's `ForegroundNotify`/`FrontmostNotify` conditions match; it is not itself a system sound switch. The proven installation overwrite bug is fixed, preserving an existing setting such as `ForegroundNotify`. A device comparison is still required before changing that feature's semantics.

A confirmed runtime-linking defect is fixed: 2.0.18's Swift `@_cdecl` center pan callback was internal and absent from the actual Mach-O dynamic export trie, so the native callback shim's `dlsym` could not find it. The C entry points are now explicitly public. CI checks the actual linked dylib export trie; source presence or a successful Swift compilation alone no longer count as proof of callback reachability.

The original ring invocation and release/collapse animations remain byte-identical to 2.0.18. The carrier still disappears on release; no pinned/always-visible override exists. A center-only decision is captured BEFORE native end clears selection and scale, consumed exactly once AFTER original end, and submitted as an ephemeral ReflectManager through the SAME original selected-App animation/admission as ordinary ring Apps. The existing action gate consumes the center-only ID before any app scene or `_floatings` entry is created and opens a separate chooser panel. This temporary model is not appended to saved Apps or any ring slot. Post-release delivery no longer reads a collapsed snapshot or requires the recognizer to still report exactly `.ended`; genuine cancelled/failed inputs remain excluded.

The center tile now uses the original white carrier with ordinary/selected brightness, 70%-width image content and whole-tile selected scale 1.45. It adds a visible center lift rather than the previous tiny finger drift. Its initial screen-center target is placed with animations disabled before scale/opacity joins the original transaction, preventing a flight from the default zero-origin point. The center is not a polar App slot, so its lift direction is explicitly upward; the native coefficient is reused without changing surrounding icon geometry.

Visibility recovery now distinguishes a known system state from an unavailable query. Present events provide a short pre-transition guard, not a permanent OR latch. Valid observed inactive state clears the mask even if a delegate-dismiss notification was not received. A separate timer owns recovery instead of relying solely on chooser ticks. Per-view setter/forced-write depth keeps subclass/superclass `setHidden:` hooks from turning a temporary forced hide into saved business intent; prehidden and user-closed surfaces stay hidden. No app launch, model removal, or forced reopen is used to restore visible surfaces.

Every newly presented floating model in a SpringBoard run also writes its current-direction native offset to zero after the existing initial-size reset and before refreshing geometry. In the original model this means physical screen center. Repeated presentation/restoration of the same manually moved model and keyboard callbacks do not run the first-model initializer again. No second animation/timer is added and no original transition routine is modified. Device verification is still required for private UIKit callback timing and first visible placement.

## Build

`python3 build.py` on macOS with Xcode's iPhoneOS SDK. The workflow is `.github/workflows/build.yml`.

The script verifies the input DEB and exact arm64e main-image SHA-256, assembles PAC-preserving entry stubs and original-entry trampolines, compiles the explicitly enumerated main/helper sources, signs each changed Mach-O file, verifies signatures, packs a Debian archive, and reads every archive member back. It recompresses only the data TAR and asserts decompression is byte-identical before packaging. The resulting file count is recorded in `build-manifest.json`. Eight original components and the gesture helper remain arm64e-only; the bundled Orion runtime is arm64e-only as well.

Only gesture entry code, the private Orion load path, and an added app-side keyboard-inset helper load command are patched. Media and package-maintenance logic are retained. The original app-side keyboard code is preserved; the helper wraps its result after the original hooks initialize. Source model offsets are specific to the supplied sample, so the script rejects other binaries.

## Orion is bundled privately

The main image imports 79 symbols from Orion. This build does not delete that code or fake its symbols: it includes the official Theos Orion 1.0.2 arm64e runtime at `Library/MobileSubstrate/DynamicLibraries/.stheno/Orion` and links to it through `@loader_path/.stheno/Orion`. The private runtime has a distinct install name `@rpath/SthenoOrion`, preventing it from occupying the usual global Orion framework path. Its Substrate dependency uses RootHide's `.jbroot` path from the parent directory.

`Depends` no longer contains `dev.theos.orion`; only the existing MobileSubstrate and firmware dependencies remain. No other app or tweak is told that a global Orion package is installed. Do not remove an Orion package that other installed tweaks need.

## Validation

Build, archive and code-signature checks do not verify behavior in SpringBoard. This package is a **device-untested test build**. Confirm hit regions, side tap/hold competition, scaling, landscape rotation, default-size restoration, multiple floating windows, and docking/un-docking on the actual RootHide device. Prior arm64e repack was reported by the user to load successfully; that report does not establish this patch's runtime behavior.
