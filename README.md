# Stheno arm64e portrait gestures (binary-derived test build)

This private project reconstructs the requested portrait-gesture dispatch from the supplied Stheno binary. It is a replacement gesture module with ABI bridges, **not a recovery of the original full Swift source tree**.

# Stheno 2.0.33 launch isolation and cached scene compatibility

Device feedback reports that 2.0.32 black-screens application launches (fullscreen and hosted) and prevents widgets from appearing. Treat that as a global regression, not another keyboard-offset issue. The added reflow constructor installed UIScreen/FBS hooks before application launch and evaluated UIApplication/scene/window state even when its policy would later reject an unhosted process. This unsafe reachability is statically confirmed; no device crash/hang stack has yet identified a unique system lock or recursion root. The former host/mock suite did not execute that startup implementation and was insufficient evidence of launch safety.

This release removes the independent reflow constructor, private FBS scene-update hook, private scene-bounds call and broad defaults-changed observer. Both client and reflow now require main-application Foundation metadata: a real APPL .app bundle, no NSExtension/appex/XPC ancestor, and no excluded system UI/widget service. The substrate UIKit load filter is unchanged, but extensions and services install no client/reflow hooks or scene observers. Loading a library is explicitly distinct from activating its behavior. The client's constructor only registers a one-shot Foundation launch/activation observer; installation is deferred until after that observed notification has returned. It does not instantiate UIApplication, query scenes, read preferences or query IPC from dyld initialization.

Reflow installs no screen hook for ordinary fullscreen/unhosted startup. Only after launch, a fresh SB hosted-layout and enabled original bit31 permit a coalesced main-queue scene refresh. The public UIWindowScene coordinate-space bounds supply the cached value; no original scene method/settings is intercepted. UIScreen.bounds then calls the saved original or returns an unexpired cache, without querying UIApplication, scenes, windows, preferences, IPC or logs. Native IMP recursion is guarded before invoking the saved implementation. Loss of key/activation, disconnection, missing hosted state, ambiguity and expiry restore native results. SB remains the only keyboard-physical authority, and geometry, no-editor-transform behavior and original animation ABI are unchanged.

New executable tests use the real production startup and reflow code, not only the pure policy predicate. A hash-locked 32 source negative control must hit a blocked-UIKit startup sentinel with no hosted layout. The new implementation must complete 200 startup/coalescing cycles, exclude widget/appex/XPC/service cases, and perform 40,000 screen reads without any application/scene traversal, as well as recover through fullscreen/expiry/native-IMP reentry. The UIKit classes are minimal macOS stand-ins, not an iPhone startup or WidgetKit render test. Existing host/client keyboard/transport and unrelated feature regressions remain enabled. On-device app first-frame and widget rendering still require acceptance; do not represent this fix as a captured-device root-cause proof.

Diagnostics use SthenoViewport33.log. After installation, all processes that still hold 32 must be restarted; a device reboot followed by the user's normal jailbreak activation is the clearest way to unload old app/extension hooks. Do not erase app data, widget configurations or plugin preferences.

Atomic layout metadata includes physical generation/visibility and hosted membership. A separate non-authoritative frame-probe stream merges app raw/mapped diagnostics into SB's shared log. No old keyboard-window transform, editor displacement, intersection hook or URL code is restored. Original card geometry mathematics, the original withAnimation/spring ABI, ring/gesture/dock/capture/preferences and legacy-removal boundaries remain. Device diagnostics use SthenoViewport32.log. Host lifecycle and cross-process transport tests now reject the formerly accepted ability of an app claim to revive a physically hidden keyboard. ## Build

`python3 build.py` on macOS with Xcode's iPhoneOS SDK. It compiles only the two source-linked dylibs and repacks the deb; every binary patch is already baked into `inputs/base-patched.deb`. The workflow is `.github/workflows/build.yml`.

The script verifies the input DEB and exact arm64e main-image SHA-256, assembles PAC-preserving entry stubs and original-entry trampolines, compiles the explicitly enumerated main/helper sources, signs each changed Mach-O file, verifies signatures, packs a Debian archive, and reads every archive member back. It recompresses only the data TAR and asserts decompression is byte-identical before packaging. The resulting file count is recorded in `build-manifest.json`. Eight original components and the gesture helper remain arm64e-only; the bundled Orion runtime is arm64e-only as well.

Only gesture entry code, the private Orion load path, and an added app-side keyboard-inset helper load command are patched. Media and package-maintenance logic are retained. The original app-side keyboard code is preserved; the helper wraps its result after the original hooks initialize. Source model offsets are specific to the supplied sample, so the script rejects other binaries.
